## 原创边界

NiBabel、nifti-rs、NIFTI-Reader-JS、NiiVue 都是明确先例。格式、算法、查看器
概念并非本项目发明。贡献是 MoonBit 可复用数据层、三个后端和独立双空间写回验证。
NiBabel 仅用于测试；Node 只承担文件、gzip、进程边界。运行时没有其他语言影像库
替代核心算法。没有虚构用户、合作单位或患者收益；后续若发现同等 MoonBit 项目，
应重新评估，而非改名规避重叠。

## 2026-09-24：必要性对照，不作“不可替代”承诺

问题不是其他语言有没有更成熟的方案——显然有。目标约束是：应用主体是 MoonBit，
希望同一影像计算核心在 JS/Wasm-GC/Native 使用，且运行时不引入 Python 服务或另一套
语言影像引擎。在这个约束下，独立的标量访问、双空间编辑和区域分析库有复用价值。
若没有这个约束，仅仅“换语言重做”不足以证明用户一定需要本项目。

| 选择 | 适合的需求及现有优势 | 本项目定位/不替代什么 |
| --- | --- | --- |
| [NiBabel](https://nipy.org/nibabel/nifti_images.html) | 成熟 Python 影像格式与科学计算工作流，[array proxy](https://nipy.org/nibabel/images_and_memory.html) 可按需加载 | 纯 Python 或大文件需求优先评估它；本项目不是更全、更快的替代品 |
| [NIFTI-Reader-JS](https://github.com/rii-mango/NIFTI-Reader-JS) | JS 应用读取 NIfTI 的现成方案 | 纯 JS 读取无须迁移；本项目提供 MoonBit 原生计算接口、双空间写回和跨后端复用 |
| [NiiVue](https://github.com/niivue/niivue) | 成熟 Web 医学影像可视化 | 需要现成查看器时更合适；本项目不包含渲染/UI、配准或完整诊断工作站 |
| 本项目内嵌库 + 批处理消费者 | MoonBit 程序中，同网格标签门控→区域时间序列→几何保持裁剪，宿主只接文件/进程 | 核心不依赖前述引擎；通过独立 oracle 检验，不宣称临床价值或全球唯一 |

新增的 [真实可执行消费程序](../examples/batch-roi.mjs) 将输入清单变为 CSV 和 `.nii.gz`，
[行为验收](ACCEPTANCE.zh-CN.md) 检查成功/失败路径以及输出数值。
**这是自建集成，不是第三方真实采用证明**。当前没有可核验的外部使用者访谈、
生产接入或合作单位；其需求强度仍是申报风险，不能靠增加行数、引用测试数量或修辞抹去。

下一阶段优先征集一个有授权数据的 MoonBit 应用使用者，记录接入步骤、缺失能力、
为什么选择/不选择此库及可复现回归案例；未获得许可的影像和身份信息不进仓库。
如果反馈显示成熟方案更适合，就记录结论并调整定位，不捏造必要性证明。

## 维护承诺的边界

维护者为本仓库作者。通过 GitHub Issues 接收最小复现，优先处理可导致错误数值、
坐标错写或不安全输出的问题；不承诺未经资源保障的响应时限。每项修复补回归用例，
发布前跑三后端与双平台 CI、独立格式读回、公开包消费和 API/源码审计。
0.x 版本可能调整 API，变更写入 CHANGELOG，已发布标签不重写；新增格式能力须先
明确兼容范围和可执行验收，再进入版本，不把路线图写成已完成成果。
